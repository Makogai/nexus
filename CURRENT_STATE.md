## 0.5.1 — the 0.5.0 release run failed on macOS (session 13, branch `fix/macos-knowledge-watcher`, merged into the milestone)

* **What failed:** release run 42828270171 (`v0.5.0`): every installer built (Windows, macOS ×2, Linux) and every other
  check passed, but *CI checks / Rust (macos-latest)* failed one test —
  `watcher::tests::documents_saved_created_moved_or_removed_are_seen_and_nothing_else_is` ("a saved document", no change
  seen in 10 s) — so the draft release was never created. Nothing was released; the tag `v0.5.0` stays where it is
  (moving a pushed tag needs a force push).
* **Cause:** macOS FSEvents names a changed file by its *real* path (`/private/var/folders/…`), while the watcher compared
  it with the path it watched (`/var/folders/…`, a symbolic link — the temporary folder). No event matched a knowledge
  root. The same would have hit any workspace reached through a symbolic link. Windows and Linux report the watched path.
* **Why CI did not catch it earlier:** the watcher (ADR-0049) landed on `main` together with the `release:` commit and the
  tag in one atomic push, and the standalone CI run skips a `release:` commit — the macOS tests first ran inside the
  release run. Lesson: run CI on the branch before it is merged and tagged (`gh workflow run ci.yml --ref <branch>`
  after the owner pushed it).
* **Fix (`692da59`):** `knowledge::watch::real_names` records each watched folder's real name where it differs;
  `watch::as_watched` maps a reported path back before `affects_index` decides; the desktop `Folders` uses both. Tests:
  a pure mapping test (all platforms) and a symbolic-link workspace test (`#[cfg(unix)]`, runs on Linux/macOS CI only).
* **Release prep (`55f9e65`):** version 0.5.1 (Cargo.toml + lock, package.json + lock, tauri.conf.json, README); release
  notes say 0.5.0 was never released. The updater offers 0.1.x → 0.5.1.

## Known issues / decisions to revisit

* Portable Workspace: manifests stay JSON (`nexus-workspace.json`, `nexus.lock.json`, `project.json`,
  `environment.json`) — the specification's YAML names map to them (ADR-0036). Project discovery scans on view load and
  on Rescan; there is no file-system watcher. Whether a remote is *private* cannot be verified for arbitrary hosts —
  trusted sync records the person's confirmation and stops when the remote URL changes. Editing a workspace skill
  withholds the skills until they are approved again (same rule as every kit). Development records need workspace
  schema 2 and the `development-records` feature; sessions from before migration 0017 have no starting commit, and
  test results are *observed* by category only — only gates NEXUS ran are *verified*. The architecture summary is left
  for a reviewed draft (skill `workspace:architecture-documentation`); NEXUS calls no model. The template library
  (v1.0.0) passed the structural gate in `templates::tests` and the P9 content review (`docs/TEMPLATE_REVIEW.md`); the
  owner's own read is MANUAL 33. A failed gate fails the whole workflow run, so workflows record findings as they go.
  The workspace skills `code-review`/`security-review` share names with Claude Code built-ins (namespaced
  `workspace:`).
* Release gates: installers unsigned until ADR-0050 is switched on (SmartScreen warns; macOS `.dmg` ad-hoc signed, not
  notarized — Gatekeeper asks); updates are signed (ADR-0044). macOS and Linux builds are verified only by CI (no local toolchain for them). The installer downloads the WebView2 runtime only
  if it is missing (preinstalled on Windows 11).
* Tauri's NSIS installer reads its options from its own path too — scripts must start it by an absolute Windows path;
  the remembered install location (`HKCU\Software\nexus\NEXUS`) survives uninstalling (ADR-0033).
* Restore replaces the whole machine-local state (database + `global/`); workspace files are in Git, not in backups.
  The desktop restores at the next start; the CLI refuses while a NEXUS host runs.
* Lock detection is best effort (LogonUI process); the displayed sender name comes from the registration (visual
  check in MANUAL_CHECKS 27). Development builds register `dev.nexus.desktop.dev` in HKCU on their first notification.
* Gates run with the user's rights; a run needs the project folder on this machine to verify. Gate approval is
  machine-local like the gates themselves: it guards against unseen command changes, not against a person approving
  a harmful command. Gates that existed before the workflow stage need one approval after the upgrade.
* Context strategy is machine-local; InstructionsLoaded costs one hook process per instruction file at start.
* Knowledge files are watched by the desktop (ADR-0049), only the active workspace's; folders whose changes Windows
  does not report (some network drives, WSL paths) still refresh on window focus and session end. The workspace folder
  cannot be renamed while NEXUS watches it. Session folders are pruned 30 days after their session ended; kit overlays
  only when their profile is gone.
* Error toasts persist until dismissed (at most four). Not yet on `useAction`: KitProfileCard, RegisterKitDialog,
  CloneWorkspaceForm, SyncPolicyCard, NewWorkspaceForm. Graphify failures are visible only in the terminal it ran in.
* `task-flow.mjs`'s hard kill (`taskkill /T /F`) failed twice in one session (a child exiting during the kill); the
  helper now prints taskkill's message.
* Usage token counts are *parsed* (ADR-0010): Claude Code's transcript format is undocumented; versions outside
  `VERIFIED_FORMATS` are flagged. Not verified with a signed-in profile yet (MANUAL_CHECKS 28). Claude's background
  helper calls are not in the per-response counts. Sessions started outside NEXUS are not attributed to projects.
* Cost estimates need the profile's billing classification (from a sign-in check); unknown billing is withheld.
* Sync: NEXUS never merges, rebases or force-pushes — diverged branches and conflicts are integrated in the person's
  Git tool. The inspection is pattern-based (common credential formats), not a guarantee; the outgoing review stays
  the person's responsibility. Kit folders inside the workspace must be registered per machine. No automatic
  background fetch (fetch is explicit).
